# Дополнение к промпту: выбор DNS-серверов из списка

> Вставлять в тот же чат Android Studio **после** основного промпта
> (`manager-app-prompt.md`), когда каркас приложения уже собирается.
> Требует модуль версии **2.1.18-r2** или новее.

---

Добавь в приложение работу со списком DNS-резолверов: пользователь выбирает серверы
из выпадающего списка, добавляет и удаляет их, либо возвращается к автоподбору.

## 1. Откуда берётся список

Список резолверов (774 сервера на момент написания) качает и проверяет подписью minisign
сам `dnscrypt-proxy`, кэш лежит в `/data/adb/dnscrypt-proxy/public-resolvers.md`.
Приложение **не скачивает его само** — читает готовый файл через модуль. Так список
всегда совпадает с тем, что реально доступно прокси, и не требует доверия к сети приложения.

Команды модуля:

| команда | вывод |
|---|---|
| `dnscrypt-ctl servers raw` | весь `public-resolvers.md` (~295 КБ) |
| `dnscrypt-ctl servers relays` | `relays.md` — релеи для Anonymized DNSCrypt |
| `dnscrypt-ctl servers list` | только имена, по одному в строке |
| `dnscrypt-ctl servers info` | путь к кэшу, дата обновления, число серверов, текущий выбор |
| `dnscrypt-ctl servers get` | активное значение: имена через запятую либо `auto` |
| `dnscrypt-ctl servers set a,b,c` | задать весь список разом |
| `dnscrypt-ctl servers add имя` | добавить один |
| `dnscrypt-ctl servers remove имя` | убрать один |
| `dnscrypt-ctl servers auto` | вернуть автоподбор по фильтрам `require_*` |
| `dnscrypt-ctl servers active` | какой сервер прокси выбрал сейчас (строка из его журнала) |

Каждая правка создаёт резервную копию конфига и применяется **только после**
`dnscrypt-ctl restart`.

**Используй `set` для применения изменений**, а не серию `add`/`remove`: приложение копит
правки в памяти и отправляет итоговый список одним вызовом. Так получается одна резервная
копия вместо десятка и нет гонок при быстрых нажатиях. `add`/`remove` оставь для случаев,
когда нужно изменить ровно один элемент.

В `dnscrypt-ctl json` для этого есть два поля:

| поле | тип | смысл |
|---|---|---|
| `servers` | string | имена через запятую либо `auto` |
| `resolvers_cached` | boolean | скачан ли кэш резолверов |

## 2. Формат `public-resolvers.md`

Файл — markdown, блоками. Один блок на сервер:

```
## adguard-dns

AdGuard DNS Default public resolver.
Blocks ads, trackers and malware.

sdns://AQIAAAAAAAAAFDE3Ni4xMDMuMTMwLjEzMDo1NDQzINErR_JS3PLCu_iZEIbq95zkSV2LFsigxDIuUso_OQhz...
```

Разбор: строка `## имя` открывает блок, дальше свободное описание (несколько строк),
дальше одна или несколько строк `sdns://…`. У сервера может быть **несколько стампов**
(разные адреса одного оператора) — бери первый для определения свойств.

## 3. Разбор `sdns://` стампов

После `sdns://` идёт **base64url без padding** (при декодировании дополни `=` до кратности 4).

Первый байт — протокол:

| байт | протокол |
|---|---|
| `0x00` | Plain DNS |
| `0x01` | DNSCrypt |
| `0x02` | DoH |
| `0x03` | DoT |
| `0x04` | DoQ |
| `0x05` | ODoH target |
| `0x81` | Anonymized DNSCrypt relay |
| `0x85` | ODoH relay |

Дальше для типов `0x00`–`0x05` идут **8 байт props в little-endian**:

| бит | значение |
|---|---|
| 0 (`1`) | сервер проверяет DNSSEC |
| 1 (`2`) | не ведёт логи |
| 2 (`4`) | не фильтрует |

**Важно: у relay-стампов (`0x81`, `0x85`) поля props нет** — сразу за байтом протокола идёт
адрес. Если прочитать 8 байт вслепую, получится мусорное число вроде `4120848833035907347`.
Проверяй тип перед чтением props; для релеев показывай только имя и адрес.

Остальную часть стампа (адрес, отпечаток ключа, hostname, путь) разбирать **не нужно** —
для UI хватает протокола и трёх флагов. Не подключай библиотеку ради этого: декодирование
base64url и чтение девяти байт — двадцать строк кода.

## 4. Экран «Серверы»

Добавь пятый пункт в нижнюю навигацию.

**Режим работы.** Наверху — переключатель между «Автоподбор» и «Выбранные вручную».
В режиме автоподбора список неактивен, и рядом текст: прокси сам выбирает серверы
по фильтрам `require_dnssec` / `require_nolog` / `require_nofilter` из конфига.
Переключение в автоподбор — это `servers auto`, обратно — `servers set` с накопленным списком.

**Выбор.** Выпадающий список (`ExposedDropdownMenuBox`) с полем поиска: фильтрация по имени
**и по тексту описания** — пользователь ищет «Quad9» или «Netherlands», а не только точное имя.
Каждый пункт: имя, протокол значком или коротким лейблом, флаги DNSSEC / no logs / no filter,
первая строка описания в одну строку с переполнением в многоточие.

**Выбранные.** Под списком — `FlowRow` из `InputChip`, по чипу на сервер, крестик убирает.
Порядок имеет значение (прокси пробует их в порядке перечисления), поэтому дай перетаскивание
или хотя бы кнопки «выше/ниже». Пустой список = автоподбор, так и скажи в тексте.

**Фильтры.** Ряд `FilterChip` над списком: протокол (DNSCrypt / DoH / ODoH), «только DNSSEC»,
«без логов», «без фильтрации». Фильтры сужают выпадающий список, не трогая выбранное.

**Применение.** Липкая нижняя панель, как на экране настроек: «Применить и перезапустить»
с числом изменений. Один `servers set`, затем `restart`, затем обнови состояние.
Пока идёт перезапуск — блокируй панель, показывай индикатор.

**Текущий сервер.** Карточка сверху: результат `servers active` (прокси пишет в журнал строку
вида `Server with the lowest initial latency: X (rtt: Yms)`). Если данных нет — покажи это
как «нет данных», а не как ошибку: строка появляется только после успешного старта.

## 5. Граничные случаи

- **Кэш не скачан** (`resolvers_cached: false`, `servers list` вернул код 1): покажи объяснение —
  список появится после первого успешного запуска прокси с работающей сетью — и кнопку
  «Обновить». Не скачивай файл сам в обход модуля: без проверки подписи minisign это
  понижает доверие к списку, а прокси всё равно пользуется своим кэшем.
- **Выбранного имени нет в кэше.** Такое законно: сервер мог быть добавлен вручную или
  прийти из другого источника. Показывай такой чип с пометкой «нет в списке», но **не удаляй**
  молча и не блокируй применение.
- **Кэш устарел** (файл старше недели по `servers info`): ненавязчивая подсказка, что список
  обновляется прокси автоматически.
- **Пустой выбор при применении**: трактуй как переключение в автоподбор, спроси подтверждение.
- **Модуль старее 2.1.18-r2**: команды `servers` нет, вернётся ненулевой код. Скрой экран
  и предложи обновить модуль — так же, как это сделано для отсутствующего `json`.

## 6. Производительность

295 КБ и 774 блока — это заметно, если делать наивно:

- Парси в фоне (`Dispatchers.Default`), результат держи в `StateFlow`, не перечитывай
  при каждом входе на экран.
- Не вызывай `servers raw` на каждый рекомпоз. Читай один раз при открытии экрана и по
  явному «Обновить», сравнивая дату из `servers info`.
- Фильтрацию и поиск делай по уже разобранному списку в памяти, с `derivedStateOf`.
- Для списка — `LazyColumn` с ключами по имени сервера.

## 7. Тесты

- Разбор `public-resolvers.md`: блок с несколькими стампами, блок без стампа, описание
  из нескольких абзацев, последний блок в файле.
- Декодер стампа: DNSCrypt (`0x01`, props 3), DoH (`0x02`, props 7), relay (`0x81`, **props нет**),
  строка с испорченным base64 — не должна ронять приложение.
- Сборка аргумента для `servers set`: порядок сохраняется, дубликаты отбрасываются,
  имя с недопустимым символом не проходит.
