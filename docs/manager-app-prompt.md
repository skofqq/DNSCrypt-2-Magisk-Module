# Промпт для Android Studio: приложение-менеджер модуля DNSCrypt-Proxy 2

> Вставить целиком в агентный чат Android Studio (Claude). Проект создавать в пустой папке,
> отдельно от репозитория модуля.

---

Напиши Android-приложение — менеджер для Magisk-модуля **DNSCrypt-Proxy 2**
(https://github.com/skofqq/DNSCrypt-2-Magisk-Module). Приложение управляет уже установленным
модулем через root-шелл; сам модуль оно не устанавливает и не собирает.

## 1. Стек и координаты

- Kotlin 2.x, Jetpack Compose, single-activity, без фрагментов.
- `minSdk 31`, `targetSdk 36`, Java 17, Gradle version catalog (`libs.versions.toml`).
- Compose BOM `2026.08.00` (даёт `androidx.compose.material3:material3:1.4.0`).
  Expressive-компоненты в этой версии помечены `@ExperimentalMaterial3ExpressiveApi` —
  включи opt-in в `compilerOptions.freeCompilerArgs`. Если понадобится компонент, которого
  в 1.4.0 нет, подними material3 отдельной строкой до `1.5.0-alpha26` поверх BOM.
- Root: `com.github.topjohnwu.libsu:core:6.0.0` (репозиторий `maven { url = uri("https://jitpack.io") }`,
  на Maven Central его нет). Модули `io`/`busybox` не нужны.
- `kotlinx-serialization-json`, `androidx.datastore:datastore-preferences`, `lifecycle-viewmodel-compose`,
  `androidx.activity:activity-compose`. DI-фреймворк не подключай — приложение маленькое,
  хватит ручного конструирования в `Application`.

## 2. Контракт модуля — единственный источник правды

Всё общение идёт через утилиту `dnscrypt-ctl`, она лежит в
`/data/adb/modules/dnscrypt-proxy-android/system/bin/` и монтируется в PATH.
Вызывать как `dnscrypt-ctl <команда>` через libsu.

### 2.1 Состояние: `dnscrypt-ctl json`

Печатает **одну строку JSON**. Поля ровно такие:

| поле | тип | примечание |
|---|---|---|
| `running` | boolean | процесс dnscrypt-proxy жив |
| `pid` | number \| null | `null` если не запущен |
| `supervisor_pid` | number \| null | присмотр за процессом |
| `port` | number | локальный порт, по умолчанию 5354 |
| `port6` | string | порт IPv6-loopback, **может быть пустой строкой** |
| `rules_v4` | boolean | правила перехвата DNS на месте |
| `redirect_ipv6` | string | `auto` \| `redirect` \| `off` |
| `tether_redirect` | boolean | |
| `private_dns` | string | значение `private_dns_mode`, бывает пустым |
| `config` | string | путь к активному .toml |
| `version` | string | версия модуля, например `2.1.18-r1` |

Разбирай через `kotlinx.serialization` с `ignoreUnknownKeys = true` и `coerceInputValues = true` —
поля могут добавиться в новых версиях модуля. Пустую строку в `port6`/`private_dns`
трактуй как «нет данных».

### 2.2 Команды

| команда | что делает | заметка для UI |
|---|---|---|
| `dnscrypt-ctl start` | запускает присмотр | |
| `dnscrypt-ctl stop` | останавливает прокси и снимает правила перехвата | подтверждение перед вызовом |
| `dnscrypt-ctl restart` | перезапуск с перечитыванием конфига | ~2 секунды, показывай прогресс |
| `dnscrypt-ctl set K V` | правит `module.conf` | **применяется только после restart** |
| `dnscrypt-ctl log [N]` | N последних строк журнала модуля (по умолчанию 50) | |
| `dnscrypt-ctl proxylog [N]` | журнал самого dnscrypt-proxy | |
| `dnscrypt-ctl rules` | текущая цепочка `nat/DNSCRYPT` | моноширинный вывод |
| `dnscrypt-ctl test` | проверка резолвинга через локальный порт | |
| `dnscrypt-ctl export` / `import` | обмен конфигом с копией на внутренней памяти | |

Коды возврата: `0` — успех, `1` — ошибка аргументов или состояния.
Stderr показывай пользователю как есть.

### 2.3 Настройки модуля (`dnscrypt-ctl set`)

Файл `/data/adb/dnscrypt-proxy/module.conf`, ровно шесть ключей:

| ключ | значения | смысл |
|---|---|---|
| `redirect_ipv4` | `true` / `false` | перехват IPv4 DNS — основной режим |
| `redirect_ipv6` | `auto` / `redirect` / `off` | `auto` перехватывает, только если ядро умеет `ip6tables nat` |
| `tether_redirect` | `true` / `false` | заворачивать DNS клиентов хотспота; по умолчанию выключено, потому что вмешательство в tethering исторически ломало раздачу Wi-Fi |
| `disable_private_dns` | `true` / `false` | системный Private DNS ходит по DoT мимо порта 53, модуль его не перехватит |
| `mirror_config` | `true` / `false` | держать копию конфига на внутренней памяти |
| `restart_delay_max` | целое, секунды (5…600) | потолок паузы между перезапусками упавшего прокси |

**Белый список обязателен**: ключ проверяй по этому перечню, значение — по типу, и только потом
подставляй в команду. Никакой конкатенации пользовательского ввода в шелл.

### 2.4 Файлы

- Конфиг: `/data/adb/dnscrypt-proxy/dnscrypt-proxy.toml` (читать/писать через root).
- Резервные копии рядом: `dnscrypt-proxy.toml-<дата>.bak`, плюс `dnscrypt-proxy.toml.new`
  после обновления модуля.
- Журналы: `module.log`, `dnscrypt-proxy.log`, `stdout.log` в той же папке.
- Копия для правки: `/storage/emulated/0/dnscrypt-proxy/`.

Разрешение `MANAGE_EXTERNAL_STORAGE` **не запрашивай** — всё делается через root.

## 3. Экраны

Нижняя навигация из четырёх пунктов.

**Состояние (главный).** Крупная карточка: работает / остановлен, время работы, версия модуля,
порт, признак `rules_v4`, режим IPv6, состояние Private DNS. Ряд действий — `ButtonGroup`
(Запустить / Остановить / Перезапустить), недоступные варианты гаси, а не прячь. Pull-to-refresh
и автообновление раз в 5 секунд, пока экран виден. Отдельная плитка «Проверка DNS» — см. п. 5.

**Настройки.** Переключатели для булевых ключей, `SegmentedButton` для `redirect_ipv6`,
слайдер для `restart_delay_max`. Изменения копятся локально; внизу липкая панель
«Применить и перезапустить» с числом несохранённых правок. У `tether_redirect` и
`disable_private_dns` — поясняющий текст под заголовком, короткий, без жаргона.
Здесь же настройки самого приложения: выбор темы и интервал опроса (см. п. 6).

**Конфиг.** Просмотр и правка .toml моноширинным шрифтом, поиск по тексту, кнопки
«Сохранить и перезапустить», «Создать копию», список существующих `.bak` с возможностью отката.
Перед записью — резервная копия. Валидация: файл не пуст и содержит `listen_addresses`,
иначе предупреди и не сохраняй.

**Журналы.** Две вкладки (`module.log` / `dnscrypt-proxy.log`) плюс вкладка «Правила» с выводом
`dnscrypt-ctl rules`. Автопрокрутка вниз с возможностью остановить, поиск, копирование, «Поделиться».

**Quick Settings Tile.** Переключение start/stop, иконка отражает `running`, подпись — порт.

## 4. Иконка

- Adaptive icon: `ic_launcher_foreground` + `ic_launcher_background` в векторе (без PNG-растров),
  плюс **обязательный слой `<monochrome>`** в `mipmap-anydpi-v26/ic_launcher.xml` и
  `ic_launcher_round.xml` — без него система не покажет themed icon на Android 13+.
- Монохромный слой рисуй отдельным вектором: одна фигура, сплошная заливка, без градиентов,
  без цвета, без теней. Система сама перекрасит его под обои. Силуэт должен читаться
  при 48 dp и укладываться в safe zone 66 dp из 108 dp.
- Мотив: замок или щит поверх стилизованного DNS-запроса — но приоритет за узнаваемостью
  силуэта, а не за деталями.
- Иконка Quick Settings Tile — отдельный `drawable` в 24 dp, только контур, `?attr/colorControlNormal`.
- Проверь результат в Android Studio (Image Asset → Legacy/Adaptive/Themed) и на светлых
  и тёмных обоях.

## 5. Проверка DNS без root

Ключевая деталь: живость прокси проверяется **без** root-вызова. Собери минимальный DNS-запрос
(A-запись, например `example.com`), отправь UDP на `127.0.0.1:<port>` из `json`, дождись ответа
с тем же transaction ID, измерь RTT. Таймаут 2 секунды, всё на `Dispatchers.IO`.
Показывай RTT в миллисекундах и признак «ответ получен». Библиотеку для DNS не подключай —
пакет собирается вручную, это несколько десятков строк.

## 6. Темы

Три режима, переключаются в настройках приложения и хранятся в DataStore:
**светлая**, **тёмная**, **как в системе** (значение по умолчанию).

- Реализация через `isSystemInDarkTheme()` в связке с сохранённым выбором — не через
  `AppCompatDelegate`, приложение чисто композное.
- Dynamic color (Android 12+) включён по умолчанию, с отдельным переключателем «Цвета системы».
  При выключении — своя палитра, задай её явно для светлой и тёмной схемы, не полагайся
  на дефолтную бейзлайн-тему.
- Все цвета берутся из `MaterialTheme.colorScheme`. Хардкод `Color(0xFF...)` в экранах
  недопустим — только в определении палитры.
- Смена темы применяется мгновенно, без пересоздания активити и без мигания белым.
- Системные панели: edge-to-edge, прозрачные, иконки статус-бара инвертируются под текущую тему.
- Проверь оба режима на всех экранах, включая моноширинные (конфиг, журналы) — контраст
  текста к фону не ниже 4.5:1.

## 7. Архитектура

```
ui/ (Compose, экраны и компоненты)
  └── ViewModel (StateFlow<UiState>, без Android-зависимостей в логике)
        └── ModuleRepository (suspend-функции, Dispatchers.IO)
              └── RootShell (обёртка над libsu: exec(vararg args): Result<Output>)
```

- `RootShell` возвращает `Result` с кодом возврата, stdout и stderr; таймаут на команду — 10 секунд.
- `Shell.getShell()` вызывай лениво, один раз, результат кешируй.
- Состояние экрана — sealed-иерархия: `Loading`, `NoRoot`, `ModuleMissing`, `Outdated(version)`, `Ready(data)`.
- Пользовательские предпочтения приложения (тема, dynamic color, интервал опроса) — DataStore;
  настройки модуля в DataStore **не дублируй**, единственный источник правды — `module.conf`.

## 8. Граничные случаи — обработай явно

- **Root не выдан или отклонён**: экран с объяснением и кнопкой «Повторить». Не падать,
  не спамить запросами.
- **Модуль не установлен** (`dnscrypt-ctl` не найден, код 127): экран со ссылкой на GitHub-релиз.
- **Версия модуля старше `2.1.18-r1`** (нет команды `json`): сообщи, что нужна свежая версия
  модуля, и предложи открыть страницу релизов.
- **Модуль установлен, но выключен в Magisk**: `dnscrypt-ctl` недоступен — отдельное сообщение;
  отличай его от «не установлен» по наличию файла
  `/data/adb/modules/dnscrypt-proxy-android/disable`.
- **Прокси упал сам**: `running=false` при живом `supervisor_pid` — покажи это как
  «перезапускается», а не как «остановлен», и подскажи открыть журнал.
- **Долгая команда**: показывай индикатор, блокируй повторные нажатия, но не всё окно.

## 9. Material 3 Expressive — как именно

Не ограничивайся сменой темы, используй выразительные средства осмысленно:

- `MotionScheme.expressive()` в `MaterialTheme` — пружинная анимация переходов и изменений состояния.
- Формы из `MaterialShapes` для акцентных элементов; смена состояния (работает/остановлен) —
  анимированная морфинг-форма, а не просто смена цвета.
- `ButtonGroup` для действий над прокси, `FloatingToolbar` на экране конфига,
  `LoadingIndicator` вместо кругового прогресса, волновой индикатор для длящихся операций.
- Крупная выразительная типографика в заголовке состояния (display/headline), плотная — в списках.
- Тактильная отдача на переключение состояния прокси и на успешный перезапуск.
- Цвет несёт смысл: работает — `primary`, остановлен — `error`, «перезапускается» — `tertiary`.
  Одного цвета мало: дублируй состояние текстом и формой, иначе экран нечитаем при дальтонизме.

Не делай: анимаций дольше 400 мс на обычных переходах, каруселей ради каруселей,
декоративной графики на весь экран.

## 10. Качество

- Строки — только в `strings.xml`, базовая локаль английская, добавь русскую (`values-ru`).
- Обработка ошибок: никаких пустых `catch`, любую ошибку показывай пользователю текстом из stderr.
- Юнит-тесты на разбор JSON (включая пустые `port6`/`private_dns`), на валидацию ключей
  `set` и на сборку/разбор DNS-пакета.
- Никаких сетевых разрешений, кроме `INTERNET` для localhost-проверки.
- `applicationId` — `io.github.skofqq.dnscryptmanager`, имя приложения «DNSCrypt Manager».

## 11. Порядок работы

1. Создай проект и version catalog, собери пустой каркас, убедись что `./gradlew assembleDebug` проходит.
2. Сделай `RootShell` + `ModuleRepository` + разбор `json`, покажи состояние сырым текстом.
3. Доведи экран «Состояние» до финального вида, потом остальные экраны.
4. Иконку, темы, Tile и локализацию — в последнюю очередь.

После каждого шага собирай проект и показывай, что именно изменилось. Если какого-то API
Material 3 Expressive нет в подключённой версии — скажи об этом и предложи замену,
не подменяй молча обычным компонентом.
